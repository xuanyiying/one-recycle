# 语音自动录入回收订单信息功能系统 - 需求文档

## 1. 项目概述

### 1.1 项目背景
本项目旨在为回收平台小程序开发一套语音交互系统，通过智能语音对话引导用户完成回收订单的创建流程，提升用户体验，降低订单填写门槛，同时保留用户手动填写的传统操作方式。

### 1.2 核心目标
- 实现语音识别交互系统，通过对话框形式引导用户提供订单信息
- 智能语音引导逻辑，根据用户输入动态调整后续引导话术
- 自动处理语音识别结果，验证信息完整性并创建订单
- 保留手动填写功能，支持语音 + 手动混合操作模式
- 语音识别准确率≥90%,响应时间≤2 秒，订单创建≤3 秒

### 1.3 使用场景
1. **纯语音模式**: 用户完全通过语音对话完成订单创建
2. **混合模式**: 用户部分信息用语音输入，部分信息手动填写
3. **手动模式**: 保留原有的完整手动填写流程

## 2. 功能需求

### 2.1 语音采集与识别
#### 2.1.1 小程序端语音采集
- 支持长按语音按钮进行录音
- 实时显示录音时长和音量波形
- 支持录音取消 (上滑取消)
- 录音时长限制：最长 60 秒
- 音频格式：AMR/MP3，采样率 16kHz 或 8kHz
- 支持录音状态提示 (录音中、松开结束、上滑取消)

#### 2.1.2 语音识别集成
- 集成微信小程序语音识别能力 (wx.getRecorderManager + wx.createVoiceRecognitionManager)
- 支持实时语音转文字 (RTA - Real-time ASR)
- 支持常见口音识别 (普通话、粤语、四川话等)
- 支持语音识别中断和重试机制
- 网络异常时支持离线缓存，待网络恢复后上传

### 2.2 智能对话引导系统
#### 2.2.1 对话流程设计
```
开始
  ↓
[问候语 + 引导语] "您好！我是您的回收助手，请问您今天想回收什么物品呢？"
  ↓
[物品类型识别] ← 用户语音输入
  ↓
[数量确认] "好的，您要回收【旧衣服】，请问大概有多少呢？"
  ↓
[数量识别] ← 用户语音输入
  ↓
[地址确认] "明白了，请问您的取件地址是？"
  ↓
[地址识别] ← 用户语音输入
  ↓
[联系方式确认] "好的，请问您的联系电话是？(如使用默认手机号请说'使用默认')"
  ↓
[联系方式识别] ← 用户语音输入
  ↓
[时间预约] "请问您希望什么时候上门取件？"
  ↓
[时间识别] ← 用户语音输入
  ↓
[信息汇总确认] "让我跟您确认一下订单信息..."
  ↓
[用户确认] → 创建订单 / 修改信息
  ↓
结束
```

#### 2.2.2 动态引导逻辑
- **意图识别**: 基于关键词匹配和规则引擎识别用户意图
- **实体抽取**: 从语音文本中提取物品类型、数量、地址、时间等实体
- **上下文理解**: 支持多轮对话，记住上文信息
- **智能纠错**: 当识别结果不完整或矛盾时，主动询问确认
- **跳过机制**: 用户可以说"跳过"或"下一个"来跳过当前问题

#### 2.2.3 引导话术管理
- 支持多套话术模板配置
- 支持话术个性化 (根据用户历史行为调整)
- 支持话术 A/B 测试
- 话术配置化，支持后台管理

### 2.3 信息验证与订单创建
#### 2.3.1 信息验证规则
- **物品类型**: 必须匹配预设的回收品类列表
- **数量**: 必须为正数，支持多种单位 (kg、件、箱等)
- **地址**: 必须包含省市区和详细地址，支持地址智能解析
- **联系方式**: 必须为有效手机号，支持默认手机号
- **取件时间**: 必须在可预约时间范围内

#### 2.3.2 信息补全机制
- 当用户语音中已包含部分信息时，自动跳过对应问题
- 示例："我要回收 5 公斤旧衣服，地址是北京市朝阳区 xxx" → 自动跳过物品类型、数量、地址询问

#### 2.3.3 订单创建流程
1. 收集完整订单信息
2. 向用户播报并展示汇总信息
3. 用户确认后调用订单创建 API
4. 创建成功后展示订单详情
5. 支持订单创建失败后的重试机制

#### 2.4.2 状态指示

- **识别成功**: 绿色对勾 + 显示识别文本
- **识别失败**: 红色感叹号 + "未听清，请再说一次"
- **网络异常**: 离线提示 + "已缓存，网络恢复后提交"

#### 2.4.3 反馈机制
- 语音播报识别结果 (可选 TTS 功能)
- 文字显示识别结果
- 关键信息高亮显示
- 错误信息友好提示

### 2.5 手动填写支持
- 在对话界面任意步骤，用户可点击"手动填写"按钮切换到传统表单模式
- 手动填写时可随时切换回语音模式，已填写信息保留
- 手动表单字段与语音采集字段完全对应

### 3.2 小程序端技术栈
- **框架**: Taro 3.x + React 18
- **状态管理**: Zustand (与现有 orderStore 整合)
- **语音采集**: wx.getRecorderManager
- **语音识别**: wx.createVoiceRecognitionManager (微信原生)
- **UI 组件**: 基于现有组件库扩展
- **网络请求**: 现有 request 工具 + WebSocket 支持

### 3.3 服务端技术栈
- **框架**: NestJS (与现有架构一致)
- **语音识别**: 集成微信小程序 ASR API / 腾讯云 ASR
- **意图识别**: 基于规则的引擎 + 关键词匹配 (参考 ai-reply.service.ts)
- **实体抽取**: 正则表达式 + NLP 库 (node-segment, node-nlp)
- **数据库**: PostgreSQL (Prisma ORM)
- **缓存**: Redis (对话状态缓存)
- **消息队列**: Bull (异步处理语音识别任务)

## 4. 数据模型设计

### 4.1 对话状态 (DialogState)
```typescript
interface DialogState {
  sessionId: string;           // 会话 ID
  userId: string;              // 用户 ID

  collectedData: CollectedData; // 已收集的数据

  updatedAt: DateTime;

enum DialogStep {
  GREETING = 'GREETING',           // 问候
  ITEM_TYPE = 'ITEM_TYPE',         // 物品类型
  QUANTITY = 'QUANTITY',           // 数量
```

## 6. 错误处理

### 6.1 语音识别错误
- **识别失败**: 提示用户重新输入，提供手动填写选项
- **网络超时**: 缓存音频数据，网络恢复后重试
- **音频质量差**: 提示用户在安静环境重新录音
- **方言无法识别**: 提示使用普通话或手动填写

### 6.2 信息验证错误
- **物品类型不匹配**: 展示可选品类列表供用户选择
- **数量格式错误**: 提示正确的输入格式
- **地址不完整**: 引导用户补充缺失的地址信息
- **手机号无效**: 提示重新输入或验证手机号

### 6.3 订单创建错误
- **库存不足**: 提示用户调整数量或选择其他品类
- **时间不可用**: 推荐其他可用时间
- **系统异常**: 保存草稿，提示用户稍后重试

## 7. 性能指标

### 7.1 响应时间
- 语音识别反馈：≤ 2 秒 (从录音结束到显示识别结果)
- 订单创建处理：≤ 3 秒 (从用户确认到订单创建成功)
- 对话状态更新：≤ 500ms

### 7.2 准确率
- 语音识别准确率：≥ 90%(普通话标准发音)
- 意图识别准确率：≥ 85%
- 实体抽取准确率：≥ 85%

### 7.3 可用性
- 支持弱网络环境：音频压缩 + 断点续传
- 支持离线模式：本地缓存 + 网络恢复同步
- 支持并发用户：≥ 1000 同时在线语音交互

## 12. 风险与挑战

### 12.1 技术风险
- 语音识别准确率不达标 → 采用多家 ASR 服务对比测试
- 方言识别困难 → 优先支持普通话，逐步扩展
- 复杂场景理解困难 → 限制场景范围，逐步扩展

### 12.2 用户体验风险
- 对话流程过长 → 优化话术，支持信息批量输入
- 识别错误频繁 → 提供便捷的手动修正机制
- 学习成本高 → 提供引导教程和示例

## 13. 成功标准

### 13.1 技术指标
- 语音识别准确率 ≥ 90%
- 意图识别准确率 ≥ 85%
- 平均响应时间 ≤ 2 秒
- 订单创建成功率 ≥ 95%

### 13.2 业务指标
- 语音下单使用率 ≥ 30%(占所有订单)
- 用户满意度 ≥ 4.5/5
- 订单创建时长减少 ≥ 50%

### 13.3 用户体验指标
- 语音交互完成率 ≥ 80%
- 用户主动使用语音功能比例 ≥ 40%
- 用户复购率提升 ≥ 20%
