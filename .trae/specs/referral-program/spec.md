# 推广功能 - Product Requirement Document

## Overview
- **Summary**: 实现一个推广功能，推广者可以邀请用户注册小程序，新用户下单后给邀请者返佣，佣金以积分形式发放，积分可以提现，推广者可以查看自己推广了多少用户，用户卖出的旧物数量。
- **Purpose**: 通过推广功能激励现有用户邀请新用户，增加平台用户量和订单量，促进平台增长。
- **Target Users**: 平台现有注册用户（推广者）和新注册用户（被邀请者）。

## Goals
- 实现邀请关系绑定机制
- 实现新用户下单后给邀请者返佣的功能
- 佣金以积分形式发放，并支持提现
- 推广者可以查看自己的推广数据（用户数量、旧物数量）
- 提供便捷的推广入口和多种邀请方式

## Non-Goals (Out of Scope)
- 多级别推广（仅限一级邀请关系）
- 推广者等级体系
- 推广数据分析报表（仅提供基础统计）
- 推广员专属客服通道
- 推广数据导出功能

## Background & Context
- 项目已有的基础：
  - User 模型已有 points 字段和邀请关系字段
  - InviteRecord 模型已存在，用于记录邀请关系
  - PointsRecord 模型已存在，用于记录积分变动
  - PointsType 枚举已包含 INVITE 类型
  - InviteService 已存在，实现了基础邀请功能
  - 完整的订单处理流程
  - 个人中心页面（profile）和积分商城（points-mall）已存在

## 推广入口设计
- **主要入口 1**: 个人中心页面（pages/profile/index.tsx）
  - 在功能菜单区域添加"邀请好友"菜单项
  - 位置建议：在"余额提现"或"交易记录"附近
- **主要入口 2**: 积分商城 - 赚积分页面（pages/points-mall/tasks/index.tsx）
  - 添加"邀请好友"任务卡片
  - 显示邀请奖励积分
- **次要入口**: 积分商城首页（pages/points-mall/index.tsx）
  - 在快捷操作区域添加"邀请好友"入口

## 邀请方式
- **邀请码邀请**
  - 每个用户有唯一的邀请码（基于用户 ID 的 base62 编码）
  - 新用户注册时输入邀请码绑定关系
- **小程序卡片分享**
  - 生成包含邀请码的小程序分享卡片
  - 好友点击卡片进入小程序，自动识别邀请码
- **海报分享**
  - 生成带二维码的邀请海报
  - 好友扫码进入小程序，自动识别邀请码
- **链接分享**（H5 平台）
  - 生成包含邀请码的分享链接
  - 好友通过链接注册，自动绑定邀请关系

## 边界条件与限制
- **邀请关系限制**
  - 每个用户只能被邀请一次
  - 用户不能邀请自己
  - 邀请关系一旦建立，不可更改或解除
- **返佣限制**
  - 仅限一级邀请关系返佣（不支持多级）
  - 只有订单状态为 COMPLETED 的订单才参与返佣
  - 取消、退款的订单不参与返佣
  - 已返佣的订单状态变更不影响已发放的佣金
  - 返佣积分最低为 1 积分（不足 1 时按 1 计算或不发放，可配置）
- **用户限制**
  - 只有正常状态（ACTIVE）的用户可以作为邀请者
  - 被邀请用户必须完成实名认证（如需）
- **时间限制**
  - 邀请码长期有效
  - 新用户注册后 7 天内绑定邀请码有效（可配置）

## Functional Requirements
- **FR-1**: 新用户注册时可以通过邀请码绑定邀请关系
- **FR-2**: 当被邀请用户的订单完成时，系统自动给邀请者发放佣金积分
- **FR-3**: 推广者可以查看自己的邀请统计（总邀请人数、总获得佣金）
- **FR-4**: 推广者可以查看邀请列表（每个被邀请用户的基本信息和下单情况）
- **FR-5**: 推广者可以查看被邀请用户卖出的旧物总数量
- **FR-6**: 佣金积分可以正常提现（复用现有提现功能）
- **FR-7**: 管理员可以在后台配置返佣规则（返佣类型、返佣金额/比例、返佣时机）

## Non-Functional Requirements
- **NFR-1**: 返佣计算必须准确且可追溯
- **NFR-2**: 推广统计查询响应时间 < 500ms
- **NFR-3**: 系统必须保证邀请关系的唯一性（每个用户只能被邀请一次）
- **NFR-4**: 返佣发放必须是幂等的（防止重复发放）

## Constraints
- **Technical**: 使用现有的 NestJS + Prisma 技术栈，复用已有的 PointsService、InviteService、OrderService
- **Business**: 返佣规则需要可配置（通过 SystemConfig），仅限一级邀请
- **Dependencies**: 依赖订单完成状态的流转，需要在订单完成时触发返佣逻辑

## Assumptions
- 订单完成状态为 OrderStatus.COMPLETED
- 返佣规则支持固定金额和订单金额比例两种方式，可通过 SystemConfig 配置
- 返佣时机支持新用户首单返佣和每单都返佣两种方式，可通过 SystemConfig 配置
- 积分提现功能已完善
- 需要提供后台管理界面配置返佣规则

## Acceptance Criteria

### AC-1: 邀请关系绑定
- **Given**: 新用户注册时提供有效的邀请码
- **When**: 新用户完成注册
- **Then**: 系统创建 InviteRecord 记录，绑定邀请者和被邀请者关系
- **Verification**: programmatic
- **Notes**: 邀请码无效或用户已被邀请时不创建记录

### AC-2: 订单完成时返佣
- **Given**: 被邀请用户的订单状态变为 COMPLETED
- **When**: 订单完成
- **Then**: 系统根据配置的返佣规则自动计算佣金并发放给邀请者，创建 PointsRecord 记录
- **Verification**: programmatic
- **Notes**: 需要防止重复返佣，记录返佣来源订单；支持固定金额和比例返佣；支持首单返佣和每单返佣

### AC-3: 查看推广统计
- **Given**: 推广者登录系统
- **When**: 推广者请求推广统计
- **Then**: 返回总邀请人数、总获得佣金、总旧物数量
- **Verification**: programmatic

### AC-4: 查看邀请列表
- **Given**: 推广者登录系统
- **When**: 推广者请求邀请列表
- **Then**: 返回被邀请用户列表，包含用户基本信息和下单情况
- **Verification**: programmatic

### AC-5: 积分提现
- **Given**: 推广者有足够的佣金积分
- **When**: 推广者申请提现
- **Then**: 提现流程正常执行，与现有积分提现一致
- **Verification**: programmatic

### AC-6: 后台管理返佣规则
- **Given**: 管理员登录后台管理系统
- **When**: 管理员配置返佣规则
- **Then**: 可以设置返佣类型（固定金额/比例）、返佣金额/比例值、返佣时机（首单/每单），配置立即生效
- **Verification**: human-judgment
