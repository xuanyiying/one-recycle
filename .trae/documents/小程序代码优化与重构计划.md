# 小程序代码优化与重构计划

经过对代码库的全面分析，我制定了以下实施计划，旨在提升代码质量、完善功能并增强系统的健壮性。

## 1. 代码清理 (Code Cleanup)
- **目标**: 移除冗余代码，提升代码整洁度。
- **行动**:
    - **移除调试日志**: 删除生产环境代码中的 `console.log`、`console.error`（保留必要的错误捕获日志）。
    - **清理注释**: 移除过时的注释代码（如 `// await sendSmsCode...`）和已完成的 TODOs。
    - **规范导入**: 检查并移除未使用的 `import` 语句。

## 2. 架构重构 (Refactoring)
- **目标**: 提高代码复用性，遵循 DRY (Don't Repeat Yourself) 原则。
- **行动**:
    - **提取常量**: 创建 `src/config/constants.ts`，将分散在各处的硬编码值（如重量选项、API 地址、正则验证规则）统一管理。
    - **统一重试逻辑**: 将 `priceEstimationService.ts` 和 `orderSubmissionService.ts` 中的 API 重试逻辑提取为通用的工具函数 `src/utils/retry.ts`。
    - **服务层整合**: 确保 `src/pages/pricing/index.tsx` 使用 `src/services/priceEstimationService.ts` 进行估价，而不是依赖前端硬编码逻辑，保持前后端逻辑一致。

## 3. 功能完善 (Functionality Completion)
- **目标**: 解决代码中遗留的 TODOs，完善业务闭环。
- **行动**:
    - **个人资料编辑 (`profile/edit`)**:
        - 实现 **头像上传** 功能，对接 `src/services/upload.ts`。
        - 实现 **手机号绑定** 功能，并在 `src/services/authService.ts` 中补充 `bindPhone` 方法。
        - 完善表单验证逻辑，使用统一的正则常量。
    - **地址管理**: 优化地址搜索功能的模拟逻辑，使其更接近真实业务场景（或预留清晰的 API 接口）。

## 4. 类型安全与质量 (Type Safety & Quality)
- **目标**: 增强 TypeScript 类型定义，减少运行时错误。
- **行动**:
    - **优化 Service 类型**: 将 `src/services/user.ts` 中的 `any` 类型替换为具体的接口定义（如 `User`, `UpdateUserParams`）。
    - **错误处理**: 确保所有 Service 调用都有统一的 `try-catch` 处理，并对接 `src/utils/errorHandler.ts`。

## 5. 测试验证 (Verification)
- **目标**: 确保修改不破坏现有功能。
- **行动**:
    - 为新提取的 `retry.ts` 工具编写单元测试。
    - 验证个人资料编辑、估价页面的核心流程。
